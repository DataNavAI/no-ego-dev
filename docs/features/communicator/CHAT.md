# Hermes chat implementation contract

Research date: 2026-10-22. Extends [SPEC](SPEC.md); proposed until verified.

## Research and decision

[Antigravity agent panel](https://www.antigravity.google/docs/agent-side-panel) documents conversations, model/mode controls and an activity toolbar next to input. [Features](https://www.antigravity.google/docs/features) documents project context. Benchmark is documentation-based, English/US; no claim of signed-in testing or measured competitor performance. Adopt persistent composer, separated project context, readable transcript and explicit activity state. Model selection, attachments and approval UI are deferred.

Library comparison before development:
- [TanStack Virtual](https://tanstack.com/virtual/latest/docs/installation): MIT framework-independent core; suitable for arbitrary list virtualization but requires bundling plus dynamic row measurement and anchor management. Best future option if continuous unlimited history replaces page navigation.
- [React Virtuoso](https://github.com/petyosi/react-virtuoso): MIT core, variable-height lists; adds React to the current native ES-module application. Its separate [Message List](https://virtuoso.dev/message-list/tutorial/message-list/) requires a commercial license and is not an open-source substitute.
- [assistant-ui](https://github.com/assistant-ui/assistant-ui): MIT React chat primitives, useful for a React app; introducing React and a build pipeline is disproportionate here.
- Decision: reuse native fetch, semantic controls and CSS; bounded 50-message network pages, at most 200 rendered messages, older/newer navigation. No new UI dependency, external CDN, telemetry, licensing expense or framework migration. Pagination bounds network and DOM work rather than merely hiding already downloaded history.

Provider authority: [Hermes API documentation](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/api-server.md) and [session route implementation](https://github.com/NousResearch/hermes-agent/blob/main/gateway/platforms/api_server.py). History supports `order=latest&limit=50&offset=N`, returns chronological rows within each page. Sessions return `data`, creation returns `session`, synchronous chat returns `message` and `session_id`. Never use stateless completions with the full transcript.

## UI brief / implementation acceptance

Extend existing [tokens](design/design-system.md). Current desktop uses a compact project toolbar, one 360px left pane (320px intermediate) with Chat, Goals and Artifacts tabs, and a flexible main Preview. There is no right pane. Selecting a tab preserves the chat DOM and draft; Arrow/Home/End keys select and focus tabs. Goals replaces the visible Goal & Tasks label. Hidden panels are inert. Below 768px, Preview is initial; the workspace switch restores the last selected left tab. Project panels remain selectable without a project and explain project selection. Preview uses validated availability and explicit new-tab Open app; it does not embed or start apps. Chat is gateway-owner scoped, independent of selected NED project; do not inject project paths. Always reopen the single canonical NED Chat session; no session list, chooser, or new-conversation action is exposed.

The header is always `NED Chat`. There is no New Conversation control, session chooser, or Load more sessions control. Available chat controls are Load older, Load newer, Latest, Reload, Message and Send. Loading: “Loading chat…” Working: “Hermes is responding…” Failure before send: “Chat is unavailable. Check the Hermes gateway, then retry.” Failed/uncertain send: “Delivery could not be confirmed. Reload the session before sending again.” Never automatically retry a mutation. Reload permits reconciliation. Preserve draft on failure. Busy disables sending. Incoming data preserves a scrolled-up reader. Latest and successful local send scroll down smoothly except reduced motion. Prepending preserves the first visible content offset. Loading older at the 200-row cap removes newest rows; Load newer or Latest restores them. No transcript or session identity is stored in localStorage or other browser storage.

## Connection / operations
After a send settles, input regains focus without moving the reader's scroll position, unless focus was intentionally moved elsewhere. User text remains literal, including Markdown-like punctuation; assistant prose uses sanitized Markdown and tool payloads stay literal. Oversized-content fallback remains plain text for bounded rendering work; when prose cannot be safely separated from structured data, its copy action is omitted.
On startup and Reload, the client POSTs an empty object to the fixed ensure route, then loads history for `nedcom-main`. COM first GETs that exact gateway ID. Only a 404 permits creation with the exact title `NED Chat` and source `api_server` (Hermes normalizes unsupported custom source labels to this supported API source); a create 409 permits one bounded re-read for a concurrent winner. It never lists sessions, adopts the latest unrelated row, scans by title, or creates a random ID. Identity/source/title mismatch and title collision are recoverable unavailability and do not modify unrelated rows. The route has no cache, so changed endpoint/key settings resolve in their own gateway context. An externally deleted canonical row may be recreated under the same ID only on a later explicit ensure; messages are never replayed. Enter sends a message; Shift+Enter adds a newline. Input-method composition and held Enter keys never submit.
`/api/capabilities` now reports `readOnly:false` and `capabilities.chat:true` because explicit chat writes are supported. Projects/tasks/files remain unchanged by chat.
When a reader scrolls up during a pending reply, retain the exact existing transcript and show “New reply available. Select Latest.” Pause older/newer pagination until Latest or Reload reconciles the changed offset window. A completed gateway response confirms delivery; read recovery failures retain the draft and never replay it automatically.

History pages require unique stable IDs. Each older/newer navigation also re-reads the latest 50-row page to check its newest ID against the retained history head before changing the displayed window. If another client changes the session, unexpected overlap/head drift displays “History changed. Select Latest to reload.” Preserve the current transcript and reading position; pause paging until Latest or Reload succeeds. Missing/repeated upstream IDs fail safely. This costs one additional bounded read per continuation, without loading the whole session.

Run `ned com` to connect to the host's default Hermes gateway. No NED-specific connection settings are needed when Hermes' API server is already configured. NED COM reads `config.yaml` and `.env` in `HERMES_HOME`, otherwise `~/.hermes`, and uses the configured loopback API port (default 8642) and key server-side. It reads fresh settings on each request, so Reload recovers after gateway setup or key rotation. Profile `.env` must be a private regular nonsymlink file owned by the current user; settings reads are bounded to 1 MiB. No credential is exposed to browser storage, HTTP responses or telemetry.

When YAML contains the API key, its opened-file owner/permission metadata must also be private/current-user. Endpoint-only YAML may retain ordinary read permissions. Neither format's credential is accepted from a symlink.

For an unconfigured Hermes installation, enable its API server with `API_SERVER_ENABLED=true`, private `API_SERVER_KEY`, `API_SERVER_HOST=127.0.0.1`, and optional `API_SERVER_PORT` in the profile `.env`, then start/restart the gateway through Hermes. COM does not change profile settings or launch/restart gateways itself. This host's default gateway was configured separately for the requested live test, keeping the generated key in its existing private `.env`.

Optional overrides remain `NED_HERMES_URL` and `NED_HERMES_API_KEY`; process `API_SERVER_KEY` is also supported. An explicit different endpoint requires an explicit credential and never receives a discovered local-profile key. Use only literal loopback HTTP origins, no credentials/path/query/redirects. Missing/malformed configuration gives recoverable sanitized 503. YAML loading uses pinned ISC-licensed [yaml](https://eemeli.org/yaml/), and dotenv parsing uses pinned BSD-2-Clause [dotenv](https://github.com/motdotla/dotenv); neither exports profile values to process.env.

Same-origin JSON POST required; origin-less writes forbidden. The browser uses fixed ensure, history, chat and turn-status routes; the existing generic session list/create adapter remains compatible for existing internal API consumers/tests but is not part of initialization. No deletes/admin/arbitrary proxy or metadata URL/query forwarding. Gateway owns persistence and execution permissions. Fixed ensure, reads and responses are bounded to the existing 15-second/4-MiB limits; ambiguous creation is recovered by the next GET-before-create ensure, never by random creation. No automatic send retry; browser draft max 8000 characters. Browser disconnect does not cancel an accepted asynchronous turn; status polling can resume while its in-memory job remains available. No stop/cancellation claim. Inside a container, loopback refers to that container: use the co-located Hermes gateway and selected profile home, rather than probing unrelated host profiles.

## Readable output (FR-022 / TC-013)
User text is rendered literally. Assistant Markdown uses locally served pinned [Marked](https://marked.js.org/) 18.1.2 (MIT) plus [DOMPurify](https://github.com/cure53/DOMPurify) 3.4.17 (MPL-2.0 OR Apache-2.0). Marked explicitly does not sanitize HTML and recommends sanitization; DOMPurify receives a narrow semantic tag/attribute allowlist. Links permit only explicit HTTP(S); images, raw forms, scripts, SVG, IDs and media are omitted. No CDN, syntax highlighter, telemetry or remote image requests are introduced. Native collapsed details retain structured tool arguments/output and unknown JSON; expanding never executes anything. Over-64-KiB content bypasses Markdown parsing without truncation. Existing VM controller tests use the real normalization/plain fallback only, while actual sanitizer behavior requires real-browser acceptance.

Research verified 2026-10-26: npm package metadata/engines/license and `npm audit --omit=dev` reported zero known vulnerabilities for this lockfile. This is not a claim of risk-free rendering. Marked 18.1.2 includes the fix for [GHSA-6v9c-7cg6-27q7](https://github.com/markedjs/marked/security/advisories/GHSA-6v9c-7cg6-27q7); TC-013 includes its pathological whitespace regression. [markdown-it security guidance](https://github.com/markdown-it/markdown-it/blob/master/docs/security.md) was considered; no framework/bundler migration is required for the chosen browser ESM boundary. Upgrade pinned dependencies deliberately and rerun actual-browser hostile-content checks.

- Journey / requirements: CUJ-008; FR-012–014.
- Level / automation: manual; procedure here, plus window logic unit assertions in TC-007.
- Preconditions: synthetic gateway with canonical `nedcom-main`, unrelated sessions, 10,000 distinct chronological messages, hostile text and a deferred chat reply. Browser at 1280x800, 390x844, 320px and reduced motion enabled; no real token visible in browser.
- Given latest page; When Load older repeatedly; Then each request fetches 50 rows, DOM never exceeds 200 messages; visible anchor does not jump. Load newer/Latest returns recent messages.
- Steps: verify fixed `NED Chat` heading and absence of New Conversation/session picker; send once while reply held and attempt double send; assert one turn. Scroll up while waiting; completion does not force bottom. Refresh and restart COM to prove the same persisted gateway turn and ID. Fail send after acceptance; draft retained and Reload required before any resend. Change project and gateway recency without changing chat identity. Inspect keyboard/focus, safe hostile text, no browser storage, no horizontal overflow, mobile workspace navigation restores the selected left tab and project sections remain reachable. Reduced motion makes Latest immediate.
- Negative cases: missing key, gateway offline, malformed/oversized replies, session deleted, very long messages, external history changes during a read, failed older page retries. No auth values or message content in telemetry/storage.
- Cleanup: stop fixtures/browser and remove test-owned external evidence. Pass requires actual screenshots, geometry/network observations and keyboard results; written cases are NOT RUN.

Rollback removes chat routes/assets and env settings without deleting sessions. Existing telemetry stays unchanged; no transcript analytics.

## Enforced provider and terminal launch boundary (ARCH-001)

Each Hermes launch/auth/setup/probe passes one preflight. Initially permit only `openrouter` with an explicitly staging-owned API-key pointer in staging `.env`; `auxiliary.*.provider=auto` resolves only to that validated main provider, fallback providers/model must be empty. Any other explicit auxiliary/provider, inherited provider override, external OAuth importer, external-process provider or cloud default chain fails before native auth/tool resolution. Codex and Qwen are denied: installed Codex resolver imports CODEX_HOME or unchanged HOME/.codex/auth.json and Qwen reads/writes HOME/.qwen/oauth_creds.json. Neither HOME nor CODEX_HOME is redirected or repurposed. Missing stage grant produces a staging-login-required result without calling native external resolver or network. Any future model-login reuse is explicit user scope and must get a separate bounded design; until answered separate login is preparation default. Model authorization remains deferred, credential-free native prompt/skill probing proceeds.

First-install staging config overlays only owned isolation settings: local terminal backend, absolute staging workspace cwd, `auto_source_bashrc:false`, `shell_init_files:[]`, no MCP/external credential-chain tools; record the overlay. Later updates preserve config; launch validates these constraints and refuses unsafe preserved changes, rather than rewriting user choices. Main config template updates are reported separately.

Disabling auto_source_bashrc alone is insufficient: native local `_run_bash(login=True)` still calls bash -l, and background shell uses -lic. Use supported native PATH/SHELL selection with a small stage-owned `bash` execution wrapper, selected by `shutil.which("bash")` and explicit SHELL. The wrapper accepts native shell argument shapes, removes login/interactive startup modes, then execs pinned absolute system bash with --noprofile --norc and the equivalent -c command. Reject unsupported argument shapes instead of silently forwarding login. Inherited BASH_ENV/ENV/ZDOTDIR and credential variables are absent. PATH begins with staging wrappers and does not include normal credential-wrapper paths. Actual native terminal init, foreground and background probes must show no shell-init sentinel read, unchanged sanitized environment, staging cwd and stage ned resolution; if any native execution path bypasses this supported wrapper, disable that terminal path until proven. No core Hermes patch or shell rc edits. A user deliberately executing arbitrary host commands remains outside state/config isolation; this is not an OS sandbox.

## Small deterministic sync controller

Proposed commands: `ned-staging-control setup/status/update/start/stop/rollback/remove`; `ned-staging` launches Hermes and `ned-staging-cli` launches task/com. Inside staging Hermes only, PATH may expose an owned `ned` wrapper pinned to current verified CLI and staging database. This never changes global ned or adds hosted-workspace lifecycle access. One root-owned recurring Codex automation calls update, quiet on unchanged healthy checks. No cron/launchd polling workaround. No gateway or always-on NEDCOM service is required. User starts NEDCOM through staging CLI on recorded fixed loopback port; update waits while it is running. Readiness probes use an ephemeral test server and close it. Stable URL is available only during that explicit user-started session. Mac sleep/offline defers updates; no always-on guarantee.

1. Acquire owned update lock and verify stale process identity. Read exact main SHA and complete configured workflow/job success for that SHA/main-push event; absent/pending/failed/cancelled/ambiguous results hold.
2. Same active healthy SHA: no rebuild/restart/profile update/data reset. Record bounded last check, no notification.
3. Build immutable candidate with private pinned Node, lockfile/digest, isolated scratch SQLite and ephemeral-port CLI smoke; native distribution plan must have supported Hermes requirement, no symlinks/runtime secret payload or missing owned paths.
4. Recheck current main and exact CI; discard superseded candidate. Validate applicable supported interface gate/evidence for exact candidate, never infer browser PASS from unrelated prior revision.
5. Defer promotion while any active staging agent session or user-started communicator/writer exists; never terminate or restart user agent work. After sessions exit, quiesce owned controller writes. Take protected full profile snapshot preserving modes plus SQLite online backup; restoration into scratch must validate. Do not print/archive secrets into evidence or source tree.
6. Record durable transaction; retarget only staging installed manifest source to immutable candidate; run native profile update preserving config. Switch CLI release pointer; source digests plus fresh native prompt/skill load and ephemeral health/project readback must pass.
7. Failure/interruption restores full stage profile snapshot, old CLI pointer and matching SQLite backup, verifies old runtime prompt/skills and bounded ephemeral CLI health. Failed recovery is explicit unavailable/action-needed; no automatic data regeneration.
8. Complete receipt only after exact SHA/profile source/owned digest/health readback. Keep last verified rollback snapshot and bounded release history; cleanup only owned paths and no symlink traversal.

Updates refresh distribution-owned skills/SOUL/AGENTS, preserve user config/auth/.env/session/memory/data. User changes inside distribution-owned files are overwritten by native design; runbook states this. Existing config intentionally does not automatically inherit main template changes; report distribution-template delta without silently overriding user config. Distribution ownership changes/removal require explicit preserved-user-data handling and tests.

## Closed durable transaction and recovery contract (ARCH-002)

One version-1 JSON transaction is atomically temp-written, file-fsynced, renamed and parent-directory-fsynced under the verified exclusive controller lock. Unknown fields/version/phases, malformed identity/path or missing producer manifest fail closed. Fields: version=1; operation_id UUID; owner {pid,process_start,controller_digest}; base {sha,profile_source_digest,cli_digest}; target same shape; snapshot {root,profile_manifest_digest,sqlite_digest,base_sha}; phase; result null until terminal; error null except failure; timestamps. Setup with no prior profile uses a distinct setup transaction (base=null/snapshot=null) and removes only partial owned setup on recovery. Promotion requires nonnull complete base/target/snapshot. No mutable path outside owned root is accepted.

Snapshot producer copies only this complete quiesced staging profile (including confidential auth/env), preserves file modes, hashes each regular relative path and rejects symlinks/special files, records base source/CLI identity and paired SQLite online-backup digest, writes manifest then fsyncs snapshot contents/parent, marks snapshot_ready. Protected root/snapshot 0700 and confidential files 0600; source evidence contains manifest/digests only, never values. Consumer verifies operation/base SHA, normalized owned paths, producer manifest digest, full file inventory/content/modes and SQLite integrity before any restore. Any mismatch/corruption stops as unavailable; do not substitute snapshots or regenerate data.

| Durable phase / boundary | Restart action |
| --- | --- |
| preparing (no snapshot; no profile mutation) | Discard incomplete owned candidate/snapshot; keep verified base |
| snapshot_ready | Verify complete paired snapshot, then rollback to base |
| source_retarget_pending / source_retargeted | Verify snapshot; restore base |
| native_update_pending / native_update_completed (including partial file updates) | Verify snapshot; restore base |
| pointer_switch_pending / pointer_switched | Verify snapshot; restore base |
| readiness_pending / readiness_verified | Restore base unless committed receipt and transaction completion both agree |
| rollback_profile_pending / rollback_profile_complete | Reapply full profile restore from same immutable verified snapshot |
| rollback_sqlite_pending / rollback_sqlite_complete | Reapply both profile then SQLite restore from same snapshot |
| rollback_pointer_pending / rollback_pointer_complete | Reapply profile/SQLite/pointer restore; verify base source + fresh load + ephemeral health |
| rollback_verified | Persist rolled_back receipt and terminal transaction |
| committed / rolled_back | Validate matching active receipt + runtime/source identities; no mutation on agreement |
| unavailable | Block launch/update and report owned recovery action; keep snapshots |

Write pending phase before each independently mutating operation; completed phase only after filesystem durability/readback. Recovery always replays the complete base restore idempotently, not partial roll-forward. Restore builds verified profile/database temporary replacements inside owned root, atomically replaces components one by one with pending/completed phases, then restores CLI pointer. Repeat interruption during recovery follows the same full replay. No agent may launch while a nonterminal transaction exists; wrapper acquires/checks lifecycle lock before loading, preventing mixed identities from being used.

Authoritative commit point is durable active receipt carrying operation_id/target/source/CLI digests followed by durable transaction committed. If crash occurs between these writes, restore base and replace active receipt with verified base; target readiness alone is never commit authority. If terminal transaction and receipt disagree or required retained identities are missing, mark unavailable and retain paired snapshots; do not guess from a symlink. Lock recovery checks owner pid/start/digest and proves no controller/profile sessions/writers exist; unknown ownership blocks. Retain complete paired snapshot until verified base rollback or target commit and both terminal receipt/transaction are durable; one previous generation may then remain for explicit rollback. Never delete the sole usable snapshot during nonterminal/unavailable recovery. Snapshot cleanup requires matching completed operation identities and excludes active/retained rollback roots.

## Implemented interface and identity clarification

Setup is `node bin/ned-staging.js setup --settings <non-secret-json>`; installed controls are status/update/rollback/remove. User starts stage com and optional demo directly and stops them with Ctrl-C. No gateway, launch agent or always-on service is installed. Setup seeds Alpha demo-app.mjs and .nedcom.json only if absent; updates preserve project files.

A clean immutable **Hermes tracked Git archive** from installed source HEAD is captured under root/hermes-runtime/<sha>, using the installed venv interpreter. Native imports bind the owned archive via PYTHONPATH; PYTHONDONTWRITEBYTECODE=1 prevents cache changes. Complete directory/file/mode/content manifest digest is checked before every native bridge call. Normal installed PROJECT_ROOT/.env is never opened; own archive .env/.op.env additions are rejected before digesting. This closes native env_loader's unconditional source-dotenv fallback, which an empty profile .env alone does not prevent. A stage .env must exist; metadata-only key-name validation permits OPENROUTER_API_KEY only, rejects .op.env and enabled external secret sources. No model grant or inference is part of setup.

Manager/bootstrap code is intentionally pinned separately from auto-refreshed distribution/CLI, with controller/bridge/Node/Python identities; manager dependencies use the retained first-release node_modules. It does not hot-replace itself; manager/native-runtime upgrades are explicit reviewed maintenance. Resolve Node/npm paths to an immutable installed generation, not mutable current symlink. Stage native archive is SHA/digest pinned and unmodified.

root/projects/AGENTS.md is reserved generated distribution context; context.json records source SHA/digest and actual native build_context_files_prompt reads it at stage cwd. First use refuses an unowned existing file; later launch/update refuses edits rather than overwrite. Rollback derives this context from its verified paired profile snapshot; Alpha/Beta user files remain untouched.

Setup ownership marker allows retry after interruption without manual lock/snapshot deletion: recover partial owned profile/pointer/receipt, rebuild generated settings/bin/manager, retain DB/projects. Incomplete releases rebuild only with matching build owner. Unknown ownership fails closed. Real killed-controller and initial retry cases execute separately from simulated-boundary matrix.

Known operational receipts retain last20; known releases retain target/prior/active plus manager dependency release; one complete paired previous snapshot remains. Unknown entries are retained; cleanup failure warns rather than rolling back a durable commit. Default retirement preserves profile/database/projects/snapshots. Config template delta is a status boolean; no user override is silently replaced. Source identity/probe/snapshot evidence is external and contains no credentials or raw task data.

## Runtime guard and interruption corrections

Native configuration is normalized by pinned Hermes `_normalize_root_model_keys` before projection. Root/nested endpoint aliases, nested provider aliases, custom provider maps and auxiliary endpoint/key/key-env/API-mode overrides fail closed; only bounded flags leave the bridge. Native primary normalization and auxiliary route-resolution probes use synthetic configuration without client requests.

Before mutable reads/imports/SQLite opens, reject symlinks and special entries in profile/control/database/sidecar/parent paths. File reads use no-follow regular-file descriptors. Runtime npm uses owned empty user/global configuration and an owned cache, without ambient npm tokens; native foreground/background probes block normal npmrc opens before contents are read.

A detached, pinned supervisor durably records its own PID/start/group before executing a child. Native foreground and background shells use that supervisor, preserving disabled shell startup and stage cwd. Completed workers clear only after verified empty-group readback. Parent death while work survives defers update/restore/removal. A completed orphan converges after its managed group empties; an interrupted worker without completion proof remains uncertain. `recover-work` refuses live/reused identities, verifies recorded managed-group/child quiescence, and retires only positively owned records. Malformed ownership or unrelated PID identities remain blocked for investigation. This covers native managed process groups, not deliberately escaped unmanaged daemons or OS sandboxing.

Retarget/update/profile/context mutations and restore replacements are flushed before completed phases: file contents, affected profile/work/data/project parent directories and replacement SQLite before rename. Injected flush failure must not produce an updated receipt. This is syscall/order evidence, not a physical power-loss test.

Hermes runtime preparation uses an owned scratch tree, pinned Git file inventory/blob/executable-mode verification, a producer receipt, durable tree flush and atomic final rename. Binary bytes remain exact; only CRLF export conversion declared by text/eol attributes in a clean repository at the pinned SHA is accepted. Existing final directories require a matching complete producer receipt and inventory; interrupted owned scratch preparation retries without blessing partial final content.

Check errors are bounded `ci_incomplete`, `build_failed`, `readiness_failed`, `promotion_failed` or `recovery_failed`; healthy active runtime and last failed check remain separate. Verified rollback retains its promotion-failure cause. Status validates transaction/receipt/pointer and release/installed identities; tampering reports unavailable. Public command errors never print caught parser or subprocess text.

# Secret Settings UI contract

Extend existing neutral COM left tabs with Settings after Artifacts. Settings is instance-level and works without a project; preserve existing Chat DOM/draft and Preview geometry. Panel id settings, role tabpanel, label Settings; keyboard uses existing Arrow/Home/End tab behavior. Mobile initially shows Preview; click the existing toolbar left-toggle (Chat, or the last selected tab label), then Settings. No drawer or new mobile navigation. Form follows existing 8px control radius, neutral borders,44px touch targets,16px fields; min-width0 and100% width, no horizontal viewport overflow.

Heading Settings; section Secrets. Helper: “Save secrets here and share only the key with NED.” Scope: “Available to NED on this instance.” Empty: “No secrets saved.” Loading: “Loading secrets…” Error: “Secrets are unavailable. Retry.” Form labels Key (placeholder ADMIN_PASSWORD), Value (password input, autocomplete new-password), action Save secret. Never prefill stored values. List each key as text with Show, Replace, Delete. Show changes to Hide and reveals exact text in readonly textarea; hide after30s, page hidden or tab leave. Replace puts only key in form, focuses Value. Delete requires inline “Delete KEY?” with Delete secret and Cancel; no confirmation dialog with value. Success “Secret saved.” / “Secret deleted.” Error “Could not save secret. Retry.” Secret values are never used in live-region announcements. Reset value on successful save. Controls disabled during requests. Late results after leaving cannot reveal. Refresh list on entering; no browser persistence or automatic clipboard.

Render desktop/mobile screenshots using synthetic values only. Existing design authority: communicator design-system.md and project UI-guidelines.md. No new dependency or theme.

## Chat secret retrieval card

Successful native ned tool results appear in chat as a bordered neutral card: title “Secret ready”, helper “Reveal this secret privately. It is not included in the conversation.”, Reveal secret button. Revealed state has readonly multiline value, Hide button, no clipboard or Copy message action. Clear within30seconds, on leaving Chat or page hidden. Error text: “Secret is unavailable. Ask NED to share it again.” Keep44px touch targets and current neutral field/action/focus tokens. Card contains no path, tool arguments or value preview; assistant/user/non-ned messages cannot create it. Desktop/mobile same component wraps within transcript width. Results appear after reply completion when canonical tool history reloads. Screenshot evidence uses synthetic secrets only.

## Chat secret entry card (#152)
Reuse the retrieval card's neutral border, spacing, focus and responsive tokens. Title “Secret requested”, key rendered as text, helper “Enter this secret privately. It will not be sent as a chat message.” Initial button “Enter secret” opens an inline form with label “Value”, password input (autocomplete new-password), “Save secret” and “Cancel”. Success “Secret saved.” replaces the form and disables further entry. Cancel clears the field; failed save clears the field and shows “Could not save secret. Retry.” Unavailable/expired request: “Request is unavailable. Ask NED to request it again.” Disable actions while saving; clear on navigation, page hidden, redraw or30seconds. No reveal, clipboard, prefill, browser persistence or chat submission. Preserve the chat draft and focus the input on entry; restore Enter secret focus on cancellation. Saving does not automatically send another model message; user can continue the conversation normally. Desktop/mobile screenshots use synthetic values only.

# API-backed task CLI

Status: source candidate. No visual interface changes.

Core owns task operations, SQLite transactions, actor/ownership checks and delivery records. CLI parsing/rendering stays in `apps/cli/`; its client uses real HTTP to `POST /api/v1/operator/task-management` with `{project,actor,operation,args}` and a private operator bearer. `project` is an absolute local directory, canonicalized by Core; this trusted operator endpoint explicitly accepts initialization paths but never a client-selected DB/profile/credential. The existing REST orchestration API remains compatible. The legacy `src/tasks.js` facade stays available to Core and compatibility consumers, not the default CLI persistence path.

Without an API URL, start an ephemeral loopback Core server against the already-selected DB/runtime, with coordinator startup disabled; request through the normal authenticated handler using a random process-private bearer; close in `finally`. This avoids introducing a persistent credential/OS permission requirement for standalone CLI use. Only backend-only construction accepts the in-memory credential override; full coordinator listeners still require the existing private token file. Configured `--api http://127.0.0.1:PORT` / `NED_API_URL` (legacy `NED_CORE_URL`) is never silently replaced by that default mode after failure. No endpoint discovery file, new daemon, OS service or automatic model execution is introduced. `GET /api/v1/operator/context` returns opaque SHA-256 runtime/DB identities. Compare against the client's resolved context before sending task arguments; URLs reject credentials, query, fragment, paths and non-loopback hosts. Configured authorization is profile-private; actor is an attribution/ownership label only. Secrets and request payloads stay out of logs.

Existing CLI methods map to a closed backend operation enum. A per-request fresh task facade uses the shared Core connection and caller actor. Its synchronous operations permit one transaction to contain the mutation plus response receipt. Read operations are not memoized. Mutation idempotency scope is project+actor; hash operation+arguments. Same key/body returns the original result, even if later graph state changes; changed key payload conflicts. CLI accepts `--request-id`; otherwise generates one, never retries automatically, and surfaces it on ambiguous transport failure. Completion retains the underlying latest-managed-attempt verification fence.

Delivery replacement uses the existing sanitizing Core validator and writer. `task delivery ID --file record.json` publishes the complete record; omitting fields clears them. Read first and intentionally preserve wanted outputs. `task delivery ID --json` reads the saved record, not a fabricated estimate. Images/documents inherit the bounded delivery contract. `task attempts ID --cursor TOKEN --json` returns20 task-scoped summaries and an opaque continuation; retain it exactly and never reuse across tasks/projects. Queued is not running. These commands never enroll/dispatch/retry an attempt.

Compatibility: retain existing public async task facade; add synchronous variants for atomic Core composition without changing public Promise behavior. Existing CLI injected factory remains a test seam, not an environment/production bypass. Ordinary commands require no external service; explicit servers may use `--database` to state the expected DB, not reconfigure the server. No automatic migration or cross-profile synchronization. Retire no public commands or records. Rollback can reinstall the prior committed runtime; Core's additive tables/records and the original task graph remain readable. Evaluation evidence belongs outside the repository; skill cases use synthetic homes and no production side effects.

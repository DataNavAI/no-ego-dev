# Dashboard UI contract

Reuse the existing user-approved [Base/Muse COM shell](../../../.projects/no-ego-dev/design/ui-guidelines.md) and [private Preview frame controls](../web-app-previews/SPEC.md). The Dashboard tab/rail/mobile navigation already exist; do not add a new navigation hierarchy. A published project app occupies Dashboard exclusively; without an app show the explicit empty state. Use one compact tab row with accessible icon Reload/Open/Close actions. Remove the Project/project-name banner and managed app title/status header; keep identity/status available to assistive technology and show visible compact failure notices. App content begins directly below navigation. The embedded app follows the product-dashboard skill's minimal mobile default; a materially different product requirement can justify another layout.

Clear frame on project/auth change, retain unrelated Preview DOM and Chat draft. Existing keyboard tab semantics and mobile Project navigation remain authoritative. Errors are local to the published app and never silently switch to another dashboard. Unsupported Hub delivery is explicit. Frame is sandboxed at a separate generation-specific origin, never a raw localhost link for remote users.

Acceptance: actual frame content/ready identity;1280×900,390×900,320×900 and200% text; chart content readable within its app; controls/retry/new tab; project-switch race and auth loss. TC-003 owns platform browser behavior and synthetic captures; skill/workflow evaluations own actual metric charts. Screenshots/recordings stay outside version control. No screenshot alone establishes correctness/delivery.

The product app default is mobile first: compact product title, period control, exactly DAU/conversions and one two-series count chart fit the initial 320×760 and 390×760 viewport. Use a brief as-of/freshness line; keep material failure notices visible. Daily rows/definitions start collapsed and accessible. Omit marketing/welcome/branding/navigation, giant headings, redundant cards and raw logs. Preserve exact data semantics and source/privacy guarantees. TC-006 and the real workflow/evaluator scenarios verify this app contract; platform frame/navigation remain separate.

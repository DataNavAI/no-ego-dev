# NEDCOM scoped UI guidelines
Scope: communicator only, separate from existing onboarding. Users browse a project's work, review artifacts and its app. Project identity precedes project content. Each section has one primary job. Plain labels: Project, Projects, Goal & Tasks, Artifacts, Preview, Retry. Recovery explains user action without exceptions/sensitive paths.

Canonical [tokens](../../../docs/features/communicator/design/design-system.md) and [brief](../../../docs/features/communicator/design/ui-brief.md) govern implementation. Use native controls and header/navigation/main landmarks, one H1, skip link, visible focus, polite loading and transition error alerts. Keep project name visible and clear stale content on project changes. Keep loading/empty/error distinct. Wrap long names. Use one logical DOM order with mutually exclusive Chat/Preview mobile views; hidden workspace views are inert. A project inspector temporarily replaces the mobile workspace and restores its opener on close. No remote resources or motion. Read-only UI must never imply editing or app startup. Use recoverable access/database/folder failure copy. No extra themes/components until a journey needs them.

Evidence required: desktop/mobile captures, 320px reflow, 200% text, keyboard and screen-reader order, contrast and focus. Reviewers inspect contracts read-only; author remediates. Browser support belongs to existing interface registry; this guideline does not claim untested support.

The current preview-oriented workspace supersedes earlier shell geometry: compact project toolbar, persistent NED Chat at left (360px desktop / 320px intermediate), flexible central Preview state canvas and optional 300px right Goal & Tasks / Artifacts inspector. Benchmark [Lovable editor](https://docs.lovable.dev/features/projects/editor); detailed adaptation in [benchmark](../../../docs/features/communicator/design/lovable-benchmark.md). Preserve Antigravity-derived message rendering. Preview remains a truthful local availability surface with explicit new-tab Open app, without embedding or automatic startup.


## Left tab workspace revision (current governing layout)
The latest user direction supersedes the right inspector. UI-AC-14: desktop has one 360px left pane (320px intermediate), with Chat, Goals, Artifacts tabs, and a flexible Preview main area. Remove all right-pane toggles and close controls. UI-AC-15: tabs select one preserved panel; Goals is the visible replacement for Goal & Tasks. Chat remains the same NED Chat DOM/session. Arrow/Home/End navigation, selected state and inert hidden panels are required. On mobile Preview is initial and the toolbar switches Preview versus the left pane, restoring its selected tab. Project tabs stay selectable without a project and explain selection. Preserve current attachment and message controls, truthful data availability and new-tab Preview behavior. Verify TC-006 controller transitions and desktop/mobile rendered captures.

Current control enhancement: use locally bundled Web Awesome Select/Option for Project, with native fallback. Theme popup, selected/check state, hover and keyboard focus to the existing neutral palette. Composer focus is a clear neutral outer-card ring; do not remove keyboard focus visibility or change chat draft/media/streaming behavior. Canonical values and build ownership: communicator design-system.md; acceptance FR-045–046/TC-027–028. No CDN assets or relaxed CSP.

Current integrated navigation follows FR-055–057: mobile opens Chat with a single-row Menu/title/Debug header, and the left modal menu contains Project, Chat, Goals, Artifacts, Settings and Preview. This supersedes Preview-first guidance above. Desktop retains left tabs, resize and Preview; Debug is a separate hideable diagnostic surface, not the retired project inspector. Protected Settings and the explicitly activated private secret retrieval card follow secret-management FR-010; no generic tool-call UI is restored.

# Fact-source and state-copy closure

Use this focused copy probe when an interface presents sourced facts or saved/following state.

## Fact-source closure

1. Inventory each factual hook, question, explanation, and result/share claim.
2. Open the exact citation URL rather than accepting a publisher name or homepage.
3. Confirm the URL resolves to the intended page, not a locale fallback, search page, consent dead end, or unrelated replacement.
4. Verify that the source directly supports every asserted fact. A source for a date does not automatically support a role or rank derived from it.
5. When a first-party page renders from a same-origin API, verify the page-to-record linkage and compare the returned record to the UI claim. Record both the human-readable citation and linkage; do not infer linkage from matching values alone.
6. If coverage is incomplete, use a source that directly supports the claim or narrow the copy to what the source supports.

Treat a dead or claim-incomplete citation as material when sourced facts are a product requirement.

## State-copy closure

For follow, save, add, or bookmark controls, record before and after:

- heading or status;
- helper body;
- control label and pressed state;
- toast or live-region message;
- accessible name;
- persistence or limitation note.

All surfaces must describe the same state. For example, after a saved item is in a list, a helper must not still instruct the user to add it. Remove the helper after success when the updated state is self-explanatory.

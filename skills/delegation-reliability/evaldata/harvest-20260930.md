# Scoped delegation-reliability harvest scenarios

## Evidence hierarchy

For a scheduled controller, assess **worker lifecycle evidence**, then **controller output history**, then **job metadata**, then **CLI execution history**. Retention makes CLI history incomplete: an empty execution table is not evidence that the controller never ran. A frequent schedule is not worker maintenance; durable worker ownership and advancement still need proof.

## Applicability boundaries

- **Restart-durable external-tracker/Kanban:** use only when unattended continuation must survive restarts and the external tracker remains canonical. Do not replace hook-only continuation when the user rejects a duplicate queue.
- **Explicit single-worker PR-first:** use only when an owner explicitly requires one global worker and PR draining before issue draining. Do not serialize independent work by default.
- **Runnable UI/design:** require journey, viewport, accessibility, and screenshot evidence only for runnable visual changes claiming product/design readiness.
- **Privacy/parser boundary matrix:** use hostile sibling-role and closure probes after a privacy, parser, schema, normalization, timeout, or concurrency finding—not for ordinary delegation recovery.

This eval is a deterministic non-mutating simulation. It must not claim that workers were dispatched or trackers/schedulers were changed.

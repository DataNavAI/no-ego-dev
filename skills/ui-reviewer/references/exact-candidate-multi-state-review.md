# Exact-candidate multi-state review

Use for a frozen settings, permission, recovery, or control design with many clean screenshots, paired annotations, a contact sheet, and a runnable prototype.

## Identity and evidence closure

Verify lineage, round, exact candidate commit/tree, evidence generation, review kind, required kinds, and pre-review-summary digest. Require local/remote candidate identity agreement and a clean checkout. Read exact Git objects or a clean exact-commit archive.

Inventory dimensions and digests for every clean capture, annotation, and contact sheet. Reconcile all declared state IDs against pixels, annotations, visible runtime DOM, controls, transitions, and source/runtime strings. A badge may cover text only when a clean paired image preserves that evidence.

## Runtime matrix

At every declared viewport and state, record visible state ID, viewport/document geometry, primary card/action/fixed-navigation rectangles, action text and disabled semantics, clearance, and horizontal overflow. Exercise every transition and target visible controls when hidden duplicate states remain in the DOM.

## Asynchronous truth

A retry or mutation must not jump directly to success. Preserve last-confirmed truth, show pending progress, prevent duplicate same-revision input, project success only after confirmation, and return failure to a truthful recoverable state. If an enabled preference is refreshing, retain an opt-out path and prove a stale refresh completion cannot overwrite newer intent, including after restart or response loss.

## Computed contrast

Collect every visible text class's computed foreground, effective background, font size/weight, opacity, and actual disabled state across all states. Recompute applicable ratios and retain representative state/text examples. Do not exempt persistent navigation/helper text merely because it is visually secondary.

Write the report and digest outside the candidate, then recheck candidate identity and cleanliness.

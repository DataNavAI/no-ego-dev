# Evidence and distribution branches

Use the smallest applicable branches below in addition to the core opportunity workflow.

## Entity × modifier autocomplete research

When authenticated volume tools are unavailable and broad entity/reference SEO matters:

1. Fix locale, language, and date. Separate broad category seeds from controlled `{entity} + modifier` probes.
2. Preserve raw query, source URL, suggestions, position, raw JSON, and a source-linked ranked candidate table.
3. Calculate recurrence from broad seeds only. Controlled probes validate a template for an entity; they do not prove organic modifier demand.
4. Audit every head-term list for adjacent franchises, products, fictional characters, similarly named entities, and noise. Keep real entities, ambiguous aliases, and fictional/franchise taxonomies separate.
5. Label rankings editorial proxy priority unless a real volume source exists. If a corroborating source throttles, preserve successes, mark the sample partial, and never rank missing entities as zero.

## Public Reddit/community fallback

When direct public pages are blocked or rate-limited, use public search, public search feeds, or reputable public archives only for discovery/inspection. Cite the original community thread URL, disclose archive use, and do not bypass private controls.

- Treat titles as discovery, triangulate several independent threads, paraphrase unless an exact short public quote is essential, and avoid archive scores/counts.
- Use an explicit qualitative evidence rubric; separate pain strength from promotion sensitivity.
- Re-check live community rules immediately before outreach. If unavailable, mark permission/rules verification pending.
- On throttling, reduce requests, cache selected public IDs/URLs for the session, and switch public paths rather than hammering an endpoint.

## Breadth-normalized portfolios

Before comparing candidates, state whether the strategic question is a broad destination, narrow utility, or monetization vertical. Classify concepts as horizontal acquisition surface, horizontal engagement loop, shared infrastructure, or vertical expansion. Compare equal MVP candidates only at similar audience breadth; preserve narrower useful ideas as reserve verticals/modules.

Map broad query families before freezing the portfolio. Do not turn curated-list counts into demand share. Under a small budget, build equal-effort broad loops, narrow with no-paid evidence and task completion, test only funded finalists, measure completed value/share/return/fulfillment, and allow `INCONCLUSIVE`.

## Permission-first community validation

Separate controlled testing from organic distribution. Panels can compare task completion; approved community traffic tests voluntary start, completion, sharing, return, and invitation in context. Never pool panel, incentivized, creator-paid, founder/friend, and organic cohorts.

1. Identify the community and exact job.
2. Read current rules and obtain moderator/admin permission before research, promotion, surveys, referrals, repeated challenges, or giveaways.
3. Offer a private working preview; disclose who built it, supported scope, privacy/data treatment, and requested test size.
4. Use the permitted format, link directly to a working value journey, and provide standalone value rather than a generic homepage/waitlist.
5. Use privacy-safe source/candidate/revision attribution, release sequentially enough to correct, and share findings back when promised.

Do not mass-DM, scrape members, hijack replies, evade moderation, use giveaways as satisfaction evidence, or publish unverified community assertions as trusted product data.

## SEO-first interactive wedge

For a consumer search destination, map query families by user job and inspect current result types. Distinguish informational content from software: interaction must materially improve comprehension, confidence, action, or repeat use.

For the complete cross-domain workflow and validation rubric, use [`seo-first-fandom-mvp-pattern.md`](seo-first-fandom-mvp-pattern.md). Despite the retained source filename, the canonical pattern applies to any suitable community, hobby, interest, or entity destination; fandom is only one example.

A valid journey is `query answer → guided learning/action → proof or useful share`. Deliver the answer immediately; signup, sharing, or navigation cannot block it. The interaction/share artifact must reinforce the same job. Start with a small manually verified catalog and treat freshness, provenance, correction handling, media rights, and internal linking as product requirements. Avoid doorway pages, filler, and unresolved biometric/privacy risks.

Validate answer completion, time to confidence, freshness understanding, actual share action, and referred-user completion. Predeclare thresholds and pair SEO probes with task tests.

## No-personal-marketing constraint

When the operator will not do outbound sales, social posting, paid ads, influencer outreach, or ongoing content, do not shortlist an idea until its discovery channel is credible. Prefer store-search extensions, established plugin/app marketplaces, or SEO micro-tools that answer recurring queries. Downgrade generic templates, consulting lead-gen, broad undifferentiated wrappers, manual-service businesses, and ideas that conflict with the operator's active business.

Use [`no-marketing-side-income-filter.md`](no-marketing-side-income-filter.md) for the full channel-first evidence and shortlist contract. This branch changes distribution feasibility requirements; it does not waive the core demand, competitor, trust, or MVP research.

For every shortlisted opportunity include:

- `distribution channel`;
- `why users can discover it without operator-led marketing`;
- `store/search evidence and competitor update/review signals`;
- `active-business conflict check`.

# Online Opportunity Seeker eval fixture

This fixture describes the expected behavior for `skills/online-opportunity-seeker/EVAL.yaml`.

A passing response should behave like a practical opportunity research operator for a given vertical. It should not simply brainstorm startup ideas. It should show how the agent would search keyword demand, Reddit/community pain, existing Google results, app-store/play-store competitors, substitutes, and review complaints, then synthesize those signals into ranked product opportunities.

For the pet services prompt, the agent should cover plausible sub-verticals such as dog walkers, pet sitters, anxious first-time dog owners, pet-care scheduling, trust/safety, emergency instructions, owner updates, sitter matching, and routine tracking. Exact source access may vary by environment, so the response may use transparent search paths and demand proxies, but it must not fabricate exact trend numbers, app rankings, review counts, downloads, revenue, or quotes.

A strong answer should create or name durable artifacts under `.projects/<project-or-vertical>/research/`, especially an opportunity map, keyword map, community pain log, competitor matrix, opportunity shortlist, and validation plan. It should rank at least three opportunities and include evidence quality, competitive gaps, MVP wedge, acquisition keywords/communities, monetization hypothesis, risks, and validation tests. It should also route follow-up work to product-manager, ui-designer, marketer, project-manager, or implementation skills where appropriate.

The requested strategy is a broad destination, but the operator will not perform outbound sales, social posting, paid ads, influencer outreach, or ongoing content. The response must compare horizontal candidates at similar breadth, separate shared search/entity infrastructure and narrow reserve verticals, and include a credible store-search, marketplace, or SEO discovery path plus an active-business conflict check for every shortlist item.

Public research is constrained. Broad autocomplete seeds and controlled entity/modifier probes must be reported separately with source, locale, date, raw evidence, and contamination checks. If direct Reddit pages are unavailable, use only public discovery/archive fallbacks, cite original thread URLs, disclose limitations, avoid stale engagement claims, and mark live rule checks pending before outreach. Community validation requires moderator permission, builder disclosure, a direct working value route, privacy-safe attribution, and separate panel/incentivized/creator/organic cohorts. Any SEO-first interactive wedge must answer the query before signup or sharing and make the interaction reinforce the same job.

The SEO-first branch is a general community, hobby, interest, or entity-destination pattern; fandom is only one possible example. A passing answer preserves `query answer → guided learning/action → proof or useful share artifact`, keeps the promised answer immediate, and rejects an unrelated game, referral loop, or social gate. It validates dated and locale-qualified query evidence separately from task completion, time to confidence, freshness understanding, actual sharing, and referred-user completion, with numeric go/no-go thresholds declared before results.

The no-personal-marketing branch is channel-first, not traffic-by-assumption. Every shortlisted item needs concrete store-search, marketplace, or SEO evidence, relevant competitor/review/update signals, an active-business conflict check, and an observable validation test that does not quietly require outbound, social, paid, influencer, or ongoing-content work.

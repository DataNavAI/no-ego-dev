# Immutable Candidate Verification

Use when a plan requires each task to pass one composite independent gate at the same immutable commit before the next task may begin.

## Core invariant

A task is complete only when the composite independent verdict is **APPROVED** for the same clean commit SHA and current base, every predeclared non-overlapping specialist bundle is also approved, and any frozen domain authority such as editorial/provenance is **ACCEPTED**. Any code, test, fixture, or evidence correction changes the SHA and invalidates every earlier immutable verdict.

Do not build, push, stage, or deploy the candidate artifact after staged-diff/pre-commit review alone. Commit first, run every authorized immutable post-commit bundle against that exact clean SHA, and only then construct the one-time artifact. Aggregate verdicts fail-closed: any composite or specialist **REQUEST_CHANGES**, domain **REJECTED**, timeout, provider interruption, missing verdict, or completed delegation whose verdict text was not preserved leaves the task and candidate incomplete even if a separate completion reviewer says **COMPLETE**. Revoke and clearly label any already-built or staged candidate discovered to lack these gates; preserve its digest and deployment evidence as rejected history, never as authorization for the next task or promotion.

Treat a late verdict and its findings separately. A verdict against an older SHA can never approve or reject the current candidate, but its reproducible findings remain useful hypotheses. Triage every late Blocking/High finding against the current exact tree instead of dismissing it as stale: reproduce it, add a regression when relevant, fix it if still present, rerun affected gates, and obtain fresh independent approval for the resulting SHA. When several reviewers finish out of order, preserve the newest exact-SHA verdict while still applying any older finding that the newest review missed.

Index durable review evidence by repository/artifact, lineage, round, candidate SHA, current base SHA, and authorized **review bundle**, nesting every bundle under one candidate generation. For an unchanged generation, one structurally valid `REQUEST_CHANGES` or `REJECTED` result closes that bundle negatively; it must route remediation and suppress duplicate review dispatch until a new generation exists. Timeout, malformed output, or missing delivery may justify one replacement only after checking the attempt's durable artifact, and that replacement should cover missing evidence rather than rerunning verified exact-SHA checks. This deduplication never converts negative evidence into approval and never allows one review kind to substitute for another.

## Risk-weighted review convergence

Use **Risk-weighted review** within every immutable gate. Prioritize hard-to-reverse or high-consequence changes such as public contracts, destructive migrations, authorization/security/privacy, payments, critical journeys, infrastructure lock-in, broad blast radius, and changes without credible rollback. Reversible nits—naming taste, cosmetic formatting, optional refactors, or minor polish that can safely be fixed later—do not block and do not justify a new candidate/review round.

Enforce **first-round completeness** for each stable scope. **Round 1** is comprehensive: inspect the full frozen candidate and return all independently discoverable Critical/Important or otherwise material findings in one deduplicated finding set with evidence and enough direction to fix each defect class. **Round 2** verifies dispositions on the corrected exact SHA. **Round 3** is final and checks unresolved findings plus correction-introduced regressions. Later-round new feedback is allowed only for remediation changes, evidence genuinely unavailable in Round 1, or a material issue that could not reasonably have been discovered earlier; it must state `Why it was not discoverable in round 1: <cause>`.

**No round 4** is permitted for the same stable scope or artifact lineage. Every correction still invalidates prior SHA-bound verdicts, but after a negative Round 3 the workflow must block and escalate rather than create and review another remediation SHA. Tests, scanners, renaming, reviewer replacement, or splitting review kinds cannot reset or waive the three-round maximum.

### Canonical round accounting

**One review round is one immutable candidate generation.** The composite reviewer and every predeclared specialist **share one candidate generation and round number**; timeout replacements remain in that round. Persist one receipt keyed by repository/artifact, lineage, round, **candidate SHA, current base SHA, and complete authorized review-bundle manifest**, with per-bundle outcomes. **A corrected candidate advances exactly one round** and invalidates every earlier commit-bound verdict. Do not admit it until every authorized bundle in the prior generation has reached a terminal verdict.

For journey analytics or domain events that claim retry/idempotency across reload, replay, or rollover, apply `references/persisted-journey-event-outbox-review.md`. Review activation and completion as one engine-owned persisted outbox: retain full envelopes and original keys until durable acknowledgement, exercise immediate-transition and route-close races at every awaited sink boundary, treat history caps as unresolved-first priority selection rather than newest-first truncation, and require bounded backpressure rather than pending-event eviction. Before re-review, run the complete global key-location matrix across active/history and activation/completion fields; reject cross-type or cross-payload ambiguity before persistence, preserve raw stored bytes on fail-closed recovery, protect acknowledged keys after reload, ensure stale async continuations cannot acknowledge/persist/render after cancellation, and ensure every browser-unavailable path installs `noindex`.

When implementation review must precede final publication/deployment authority, avoid a circular `candidateGitSha === HEAD` attestation. Apply `references/non-circular-approval-envelopes-and-cfn-validation.md`: freeze source bytes outside the repository, exclude only a fixed set of independently anchored approval envelopes, and make live preflight re-verify exact Git source closure plus every reviewed payload digest before OIDC or mutation. The same reference covers candidate-wide machine-path scanning and deterministic compact CloudFormation validation under AWS's inline template-body limit.

For product-source plus publication-hub workflows, follow `references/multi-repo-static-review-release.md`: freeze and approve the product tree first, pin its resulting immutable commit in the hub, generate and verify the committed site snapshot, then freeze/review the hub candidate. A scratch build is not the release snapshot, and any late code, test, documentation, rendered-artifact, or evidence-label correction invalidates old exact-tree reviews. When editorial records pass through first review, independent second-review eligibility, second signatures, final publication authorization, implementation approval, and protected environment promotion, also apply `references/publication-to-deployment-authority-chain.md`; it closes signed release receipts, review/report chronology, deterministic upload manifests, exact workflow/controller environment contracts, and external DNS readback. For authenticated browser-review systems with migration, agent CLI, and CloudFormation execution roles, also apply `references/private-review-system-release-gates.md` before freezing either tree. That gate requires exact API-parity validation before persisting migration retries, environment-specific OIDC **and CloudFormation execution roles** with closed transitive `iam:PassRole`, secret-bearing CloudFront reads scoped per environment, environment-prefixed change-set scopes, and control-plane-pinned credential destinations with per-hop same-origin redirect enforcement.

## Workflow

1. **Recover the actual candidate state**
   - If an implementation agent timed out, treat the worktree as potentially useful partial work rather than restarting blindly.
   - Inspect staged and unstaged scope independently before editing; never overwrite concurrent changes.
   - Retrieve the agent's actual result when available, but trust repository state and executable verification over its self-report.

2. **Preserve strict TDD evidence**
   - Record a focused executable RED for each new behavior.
   - Apply the smallest correction, then run focused GREEN.
   - Refactors may follow a green behavior test but must preserve the same behavior suite.
   - Prefer behavioral tests over source-string or copied-status assertions.

3. **Verify the vertical slice**
   - Run focused feature tests, related integration tests, and the canonical suite.
   - Exercise real artifact writers or browser/test harnesses when they are part of the acceptance boundary; inspect the emitted structured artifact.
   - Snapshot `git status --porcelain=v2` before generation-heavy tests or builds. A green command may still modify tracked output and create new untracked route/artifact trees.
   - Run the canonical build and restore generated tracked output afterward unless publication is explicitly authorized. Remove only artifacts proven to have been created by that command; never use broad cleanup when the pre-command snapshot contained user work.
   - Re-check HEAD, staged paths, unstaged paths, and untracked paths against the snapshot before reporting verification complete.
   - For repository-wide residual-name/content gates, inspect the Git object itself with `git ls-tree -r --name-only <SHA>` and `git grep <SHA> -- .` (or equivalent blob iteration). Do not rely on ordinary filesystem search alone: ignore rules and hidden roots such as `.env.example`, `.github/`, and `.projects/` can silently escape it. Require paired zero-match evidence for tracked path names and tracked blob content at the exact candidate SHA.
   - Remove disposable evidence created solely for verification.

4. **Prepare exact scope**
   - Run syntax/static checks and `git diff --check`.
   - Confirm only authorized durable files remain changed.
   - Stage exact paths yourself when scope is unambiguous; do not ask the user to perform safe mechanical staging.
   - Review staged and unstaged diffs separately and require an empty unintended remainder.

5. **Independent pre-commit review**
   - Give each fresh reviewer the frozen requirements, staged scope, exact verification commands/results, explicit no-edit/no-commit instructions, and the absolute repository or isolated-snapshot path. Repeat the path and index-tree/SHA identity inside every batch task's own context and goal; parallel workers do not inherit the parent's working directory or another task's context. A verdict from the wrong checkout is absent, not negative evidence.
   - Name the review phase and scope explicitly. A pre-commit implementation-slice reviewer should assess whether the code is ready to become a candidate; it must not fail merely because artifact digests, deployment revisions, or staging evidence are intentionally produced later. Conversely, never present a phase-scoped implementation PASS as completion of the full candidate/deployment task.
   - Require a fail-closed `APPROVED` or `REQUEST_CHANGES` verdict with reproducible Critical/Important findings.
   - If changes are requested, fix via RED/GREEN, rerun all affected checks, and obtain a fresh pre-commit review.

6. **Create the immutable candidate**
   - Commit only after pre-commit approval.
   - Record the exact SHA and verify the worktree is clean.

7. **Run the immutable composite gate at that SHA**
   - One fresh independent composite reviewer compares frozen requirements to the exact commit and inspects correctness, security, maintainability, tests, regressions, and operational risk before returning `APPROVED`, `REQUEST_CHANGES`, or `INCOMPLETE`.
   - Add a frozen specialist bundle only when the readiness plan predeclares a named, non-overlapping, hard-to-reverse expertise boundary (for example editorial provenance, cryptography, payments, or destructive migrations). Every authorized bundle reviews the same candidate generation.
   - Reviewers must not edit the repository. Every prompt must name the absolute checkout path and immutable identity independently.

8. **Advance only after aggregate completion**
   - Mark the task complete only after the composite verdict and every predeclared specialist verdict approve the same SHA.
   - Do not start Task N+1 while any authorized bundle is absent, active, incomplete, or stale.

## Fail-closed rules

- Passing tests alone do not complete an immutable task.
- When a corrected candidate claims a public-artifact boundary, independently mutate emitted allowlisted files and recompute their manifest digests/lengths before rerunning the checker. A path allowlist plus checksum closure proves byte identity, not semantic safety; named-marker regressions do not establish broad secret/private-byte exclusion. Apply `references/exact-commit-public-artifact-boundary-review.md` and fail closed if any recognizable synthetic provider credential or prohibited publication payload survives inside an otherwise valid allowlisted file.
- A verdict against a dirty worktree is not an immutable gate.
- A correction after review invalidates that review. The three-round cap is a stop/escalation boundary, never an approval waiver: if Round 3 finds a material issue, preserve the finding and keep the PR draft/unmerged. The owner may simplify, split, or stop the scope, but cannot authorize Round 4 or substitute risk acceptance, tests, or scanners for missing independent exact-SHA approval.
- Copied `READY`, `PASS`, or Markdown labels are not evidence; derive decisions from structured data.
- Matching two caller-controlled timestamps does not prove freshness. Separate artifact `generatedAt` from a trusted evaluation clock, enforce a bounded age/future-skew policy, bind every component timestamp to the report generation, and explicitly probe the paired-stale case. Document the evaluation-clock trust boundary: if an untrusted caller can choose both clocks, the check is not security-grade freshness.
- Keep production and test trust boundaries distinct. A production report API should accept only a verified opaque candidate and derive evaluation time internally; deterministic clock/verifier seams must be unavailable to production imports. Capture test-mode eligibility and manifest trust anchors once during module initialization rather than consulting mutable environment variables at call time. Add a production-import regression that flips `NODE_ENV` afterward and proves both seams remain unavailable.
- Capturing a clock constructor or `Date.now` is incomplete when later calls still dispatch through mutable prototype methods. Capture every intrinsic used by the security decision (`now`, parse, `toISOString`, `valueOf`, or equivalents) at initialization and invoke those captured functions directly. Probe late global and prototype mutation after import; it must not backdate the production evaluation timestamp.
- Repeated self-declared release IDs do not independently bind evidence to a candidate; require hashes, immutable manifests, or equivalent provenance where readiness depends on that binding. Pin the manifest digest outside supplied evidence before module/process initialization, verify every canonical component digest before creating an unforgeable in-process handle, and include the trusted manifest digest in the final report.
- Structural validity, uniqueness, aggregate counts, and plausible identifier syntax do not prove exact-cohort identity. Bind ordered authoritative tuples (for example rank, stable ID, entity type, and canonical path) to a reviewed immutable digest, then add a syntactically valid non-cohort substitution regression.
- Cross-group identity closure must be derived from the complete authoritative reviewed group cohort, never from a narrower editorial alias, ingestion, headline-recognition, or refresh list. At a trusted current clock, probe the exported final publication predicate and the real selector with otherwise-valid `primaryArtistSlug: A` / `group: B` pairs for distinct reviewed groups, including groups omitted from narrower aliases. Require final-gate rejection even if the selector independently rejects; direct CMS/API/database callers may bypass selection. Pair this with both directions of the individual-parent matrix: a positive record where `primaryArtistSlug === idol` and `group` is an authoritative parent, and an otherwise-identical negative record with an unrelated explicit group. Build parent bindings from reviewed relationship sources with explicit per-identity precedence: ambiguous fallback catalog keys must be dropped, and the presence of an individual in a higher-authority passport/release source must shadow fallback relationships even when its authoritative parent set is empty. Seed override entries for every authoritative individual rather than only those having `member_of` edges. Validate known anchors at initialization, and fail closed for unproven explicit parents—including solo artists with no parent. Treat equality as an adversarial branch, not an automatic consistency proof: an explicitly individual-owned record with `group === primaryArtistSlug` must reject unless that self-parent edge is explicitly authoritative, and an unknown `primaryArtistSlug === idol === group` must reject. Structure the predicate by entity kind first; reserve ordinary `primaryArtistSlug === group` acceptance for genuinely group-owned records. Probe both reviewed self-parent and unknown self-parent controls directly because a guard shaped like `primaryArtistSlug !== group && !parents.has(group)` skips authorization on equality. A group/group cross-product alone does not close individual-route substitution. See `references/cross-group-substitution-closure.md`.
- Missing, stale, duplicate, malformed, or cross-candidate evidence cannot produce readiness.
- Treat a checksum manifest as part of the immutable identity even when it does not list itself. Pin its expected digest and count before review, require the same file/digest/count after the only authorized report write, and run verification under `set -euo pipefail` with explicit existence and exact-OK-count assertions. A later successful shell command must never mask an earlier missing-file or checksum error. If the manifest disappears or changes, do not regenerate it from the mutable checkout: record the concurrent mutation, preserve pre-verified findings only as generation-bound results, and withhold the immutable verdict. See `references/frozen-evidence-integrity-and-privacy-audit.md`.
- Multi-file evidence publication must have one atomic visibility boundary; locks plus sequential renames can still expose mixed or partial releases. A plain directory rename may replace a race-created empty destination on some platforms, so an immutable final name also needs no-replace commit semantics (for example, an atomic exclusive symlink/pointer to a complete hidden bundle, or a platform no-replace rename primitive). Test the destination-appears-during-prepare race, not only a destination that existed before the function started.
- Privacy-safe analytics capture seams must reduce validated inputs to allowlisted counters at observation time. Do not clone or retain full persistence records or provider payloads merely to count them later; snapshots can look sanitized while secrets and pseudonymous identifiers remain reachable in the seam's closure. Clear retained count state on disposal and instrument clone/copy boundaries in tests to prove sensitive envelopes were never captured.
- Any new runtime import changes the packaging dependency graph. Update every image/bundle/installer boundary, add a dependency-closure regression, and exercise the actual packaged artifact with startup plus a health probe; a source build can pass while the production container still lacks the imported file.
- Do not retain disposable screenshots, traces, generated output, or local candidate reports in the commit unless the frozen plan requires those exact artifacts.
- A complete automated browser/device matrix is not a substitute for an audience-seeded product review. If the critical journey remains ambiguous, unhelpful, or visually untrustworthy, record the technical metrics separately but hold the release. Any content/model/rendering correction creates a new candidate and requires fresh candidate-bound evidence and review.
- Evidence privacy applies to archive members and machine-readable metadata, not only visible report text. Scan working files, staged blobs, trace ZIP members, JSON path fields, and logs for absolute home paths and other machine-local identifiers. Prefer generating browser evidence from a detached exact-SHA worktree under a non-user-specific temporary root so trace stacks never acquire a personal checkout path, but do not confuse that with full path sanitation: absolute `/tmp/...`, `/private/tmp/...`, `file://...`, and equivalent executor-local paths are still machine-local path disclosure when the contract forbids local identifiers **or paths**. Treat aliased roots as separate hostile representations: on macOS, test both lexical and realpath spellings of system temp and var-folders roots, and test Windows profiles with both separator styles. Mirror every detector representation in packaged tests (macOS home, Linux home, both Windows separators, both temp aliases, both var-folders aliases, and local-file URI forms), then run the real freezer against the complete source before final freeze; green fixture tests do not prove historical governance prose or detector literals can be packaged. A valid baseline plus one rejection per broad class is insufficient when another spelling is accepted; report the complete representation matrix. Recursively inspect `trace.stacks` and every other member, not only visible trace/network text. For every ZIP-based payload, inspect member names and decompressed bytes in memory under explicit member-count, member-size, aggregate-size, nesting-depth, encryption, and traversal limits; cross every prohibited representation with direct, ZIP, and DOCX fixtures. After sanitizing, regenerate every affected digest/checksum/manifest, restage exact files, recursively re-scan the staged archives, and freeze a new review tree; a sanitation script's success count alone is not proof. Do not repeat a forbidden path prefix literally in the durable report merely to claim it was absent, because byte-oriented integrity scans will flag the explanatory prose too. See `references/release-report-and-browser-evidence.md` and `references/frozen-evidence-integrity-and-privacy-audit.md`.
- Treat the process-level exit as part of the evidence receipt. A browser runner can print every test body as passing and then fail in an `after` hook because the immutable evidence destination already exists; `13 pass` in a transcript is not a PASS when the command exits nonzero or contains a trailing teardown failure. Capture one clean run from an empty evidence namespace, preserve its exit-zero log, and never rerun a no-replace publisher into the same destination. Candidate-bound CUJ receipts must intrinsically include release digest, source SHA, candidate generation/deployment time, trusted fresh verification time, interface/UA class, and one result per authoritative cohort row; a copied static fixture timestamp or an external report claiming the binding is insufficient. After any evidence rerun, derive report metrics from the canonical machine-readable artifact and programmatically compare every target row before freezing review—manually copied LCP/byte tables routinely become stale even when hashes and screenshots are valid.
- Enforce review-clock chronology as a hierarchy: every nested `checkedAt` must be no later than its entity parent, every entity clock no later than the registry clock, and registry `checkedAt` no later than `generatedAt`. Add a recursive regression over the trusted parsed artifact so a newly reviewed child cannot be published under an older parent/generation timestamp.
- Re-run the exact bare canonical test and build commands immediately before staging or deployment, even when the same SHA passed earlier. Time-sensitive source inventories, freshness windows, moderation state, and generated outputs can drift across calendar boundaries without a code change. Treat a newly exposed brittle test as a candidate blocker, not as permission to rely on an earlier green transcript.
- Before a workflow that should build an immutable candidate exactly once, inspect environment branch/tag policies and read the Dockerfile, every artifact-generation step that precedes it, and every called smoke/rollback script. Reproduce the complete assembly order: if the image copies generated output, generate it immediately before Docker construction and do not restore it until the digest exists. A direct `docker build` from a clean source checkout can package stale restored assets while still succeeding. Reproduce freshness, expected-revision, database/readiness, public-marker, and semantic all-route/schema assertions before dispatch; `health.ok` alone is insufficient. For mutable feeds, execute a deterministic parser-shaped trusted row through the full parser→dedupe→refresh→final-publication path, covering both compact `sourceUrl` and canonical typed receipts, then run a real bounded refresh and distinguish fetched rows from accepted rows before trusting `lastSuccessfulRunAt`. Confirm the immutable tag does not already exist. Pull and exercise the exact digest locally before staging. If semantic verification rejects it, preserve the digest, never stage or overwrite it, rotate candidate identity, repeat immutable review, and build the replacement with corrected assembly order. If an exact reviewed branch needs temporary environment eligibility, use the narrowest exact policy, record its ID, and restore the original policy set after success or failure.
- A finite feed plan is not bounded network execution. `Promise.allSettled(feeds.map(fetch))` still launches the whole matrix at once, so never persist or report a mode such as `sequential-bounded` unless a fixed-size worker pool enforces it. Preserve input-index result order and fulfilled/rejected semantics for query-level error attribution; validate a conservative concurrency ceiling; and add an instrumented async regression that measures maximum in-flight work, includes a rejection, and proves both the ceiling and stable result index. When expanding a freshness-gated feed, probe query variants in scratch first, preserve the fail-closed minimum and final publication policy, and distinguish successful queries, fetched rows, and accepted rows. See `references/bounded-feed-refresh-expansion.md`.
- Source-backed feed transport checks are not editorial approval. For current-card inventory, independently reject cross-artist assignment, group-plus-unrelated-individual headlines, generalized clickbait variants, and gossip/speculation. Harden ingestion with a predeclared adversarial matrix covering connector case/punctuation/symbol variants and rerun the real refresh; do not merely delete today's bad rows or enter a one-regex-per-review treadmill. Treat the parser as acquisition/normalization, not the final trust boundary: the final publication gate must rerun title/entity safety so direct database inserts cannot bypass policy. For aggregator feeds, preserve the article URL, publisher label, and publisher origin from source metadata; bind the label to a finite reviewed hostname map, require every declared/rendered receipt label to agree exactly, and carry that origin through normalized, compact, generated, passport/current-card, and public API projections. `https` plus an allowlisted label—or an opaque aggregator token without publisher-origin binding—must never authorize publication. Derive secondary identities from the authoritative reviewed catalog and fail publication/startup closed when that catalog is absent or malformed; an incomplete fallback widens trust. Omit absent optional fields instead of projecting own `undefined` values, then test the complete positive path from raw record through normalization, immutable page-model cloning, bounded selection, and rendered card. Treat both normalization and the exported final publication function as hostile-object boundaries: every authorizing field must use own-data descriptor reads without invoking getters, and redundant URL evidence must agree across the top-level URL, every typed receipt entry, and the rendered action URL. Distinguish a genuinely absent optional field from a malformed accessor-backed or inherited field: malformed metadata must reject the record even when another valid receipt could otherwise supply a fallback, or the fallback launders conflicting provenance. Apply the same descriptor validation before identity fallback for every entity type (individual and group); an accessor-backed authoritative identity must not be ignored in favor of a matching secondary identity, and a matching authoritative identity must not short-circuit validation of a conflicting or malformed explicitly present secondary identity. Probe both contradiction directions, throwing getters with no fallback, and malformed optional fields alongside valid receipt fallbacks, asserting rejection and zero getter calls. Validate the original hostile record before any lossy publication projection, then validate the projection too: otherwise extra receipt entries, inherited provenance, symbols, or secondary action URLs can be erased and laundered. Close the complete top-level own-key schema rather than rejecting only names containing `url`/`href`; aliases such as `alternateReceipt` and `actionReceipt` are still provenance. Close every permitted nested object and array as well: define exact own-data schemas for media, legacy/raw snapshots, trust metadata, artist/entity arrays, receipts, and actions; reject unsupported non-empty nested structures; type-check every allowlisted nested value; and bind all nested URL representations to the canonical receipt. Before re-dispatching review after one nested-shadow finding, inventory every allowlisted retained field and run a bounded one-field mutation matrix across identity, title/body/summary, type/status/trust, schedule/time, action, route, and receipt metadata; fixing only the named examples creates a serial review treadmill. Any refresh that advances canonical verification time must rewrite every bound receipt timestamp in the cloned graph and re-run the emitted row through the final publication gate before counting it. At every untrusted array boundary, read `length` and elements only from own data descriptors, impose a practical maximum before looping, and reject holes, named properties, symbols, and extra keys. An allowlisted parent key must never authorize arbitrary child objects. Inventory legitimate projection metadata (for example ranking fields), require every allowed top-level key—not only authorizing fields—to be an own data descriptor, and type/bound paired projection metadata before preserving it. Constrain navigation `href` with browser semantics: reject backslashes/control characters, resolve against the production origin, require exact same-origin resolution, and bind the resolved pathname to the record's canonical route identity (for example exactly `/content/<slug>`); same-origin `/admin`, dot-segment aliases, sibling routes, and slug mismatches are still provenance substitutions. Preserve valid query/hash context byte-for-byte. A `^/(?!/)` regex or origin-only check is insufficient. Preserve validated projection-only fields byte-for-byte, omit absent fields rather than creating own `undefined` keys, and pass real public API items back through the exported gate. Validate captured `Object.prototype` and `Array.prototype` baselines at publication entry even for direct-URL records with no nested receipt array; otherwise nested checks can mask post-import prototype pollution. Reject every post-baseline addition with no convenience exceptions and update formerly permissive regressions to expect fail-closed rejection. At server/CMS collection boundaries, invoke the protected validator before any ordinary field read, require publish/verification status via own data descriptors, and catch row-level proxy/getter failures so malformed content rejects instead of crashing the endpoint. Validation does not make a hostile object stable: never validate a row and then compact it through ordinary property reads. Capture one immutable null-prototype/plain-data snapshot recursively from validated own data descriptors (or make the compactor descriptor-only), reject unsupported prototypes/cycles/symbols/accessors, then run the final publication gate against that exact snapshot. Iterate the outer collection through descriptors as well. Probe a stateful `Proxy` whose descriptors remain valid while its `get` trap returns different values; require zero `get` calls and either one coherent revalidated snapshot or fail-closed rejection—acceptance is valid only when the published row comes entirely from that snapshot with no provenance substitution. For title safety, test separator/case/order/possessive equivalence classes together with valid single-artist controls, and bound title length before any repeated slice/normalize scan. See `references/source-backed-feed-publication-gates.md` and `references/adversarial-publication-boundaries.md`.
- A failed rollback step does not prove infrastructure rollback failed: the old image may have been restored and then failed the same freshness smoke. Verify stack status, configured image/revision, service operation, and live endpoint revision independently. Preserve failed candidate digests/run IDs, and build a replacement only after fresh source/data review.
- Keep contract coverage deterministic: use fixed fixtures for positive renderer/type behavior, and test live or reviewed inventory separately. Never require a changing moderation inventory to contain a currently publishable sample of every taxonomy. If that assumption fails, prove RED, correct only the test boundary, rerun the full generation-plus-test pipeline, restore tracked output, and create a new candidate SHA with fresh reviews.
- Freeze every asynchronous review input before dispatch. Copy generated UI/evidence to a uniquely named non-repo snapshot, record the exact SHA/status, and then leave the shared checkout untouched until the reviewer finishes. If builds, generators, restores, cleans, or staging operations ran concurrently in that checkout, repository/file observations are not candidate-bound; preserve useful hypotheses but re-run the verdict against a stable snapshot or separate worktree.
- Immutable candidates must remain executable without writing into themselves. Tests that create temporary files, caches, screenshots, compiled bytecode, or mutation fixtures must use a scratch root outside the candidate and receive an explicit trusted `base_dir`/package-root seam when relative-path containment is under test. Never weaken lexical `.`/`..` rejection merely so a test can reach an external temporary directory. Before dispatch, run the canonical suite from the read-only candidate itself and verify its process exit code; a suite that passes only in the mutable source tree is not candidate-bound evidence.
- A checksum-closed candidate can still be semantically incomplete. Before generating the checksum manifest or making a file bundle read-only, resolve every manifest-declared local URI, README/source-sheet inventory claim, governed rights receipt, quarantine original, placement inventory, and verifier report inside the assembled candidate (or a separately pinned restricted package), then probe representative runtime evidence URLs. Keep regeneratable capture output in a disposable subtree and governed evidence in a non-destructive subtree; capture/build scripts must never replace the parent evidence directory. If assembly omits evidence, reject that candidate, restore/reproduce evidence only in the mutable authoritative source, create a new immutable identity, and repeat candidate-bound review. See `references/immutable-bundle-assembly-preflight.md`.
- A correct source hash does not prove that evidence supports the intended entity or claim. Bind the public claim through its private reviewed claim and executable typed locator to pinned evidence bytes, then bind the parsed provider ID/name and canonical URL to a separately reviewed authoritative entity mapping. Reject caller-consistent substitutions where source ID, URL and payload were changed together. Close every nested schema and enum, reject lexical `.`/`..` before normalization, and distinguish implementation approval, content-publication approval and deployment promotion. Use the hostile matrix in `references/semantic-source-contract-closure.md`.
- A reviewer signature over only reviewer ID plus record digest does not authenticate the review outcome, timestamp, record identity, or release binding. Sign a canonical versioned envelope containing every reviewer-owned assertion. Exclude lifecycle/review fields from the reviewed-record digest only at that record's top level; recursive omission of generic keys such as `status` can erase nested governance dispositions. Probe valid-looking timestamp/outcome changes, nested disposition changes, identity/release substitution, and recomputed attacker-controlled hashes without private keys. Use `references/signed-semantic-review-receipts.md`.
- Separate production-truthful UI evidence from deterministic state fixtures. Honest empty production inventory must remain empty; prove populated, fallback, error, and interactive component states with labeled fixed fixtures rather than fabricating production content.
- For static renderers that repeat a shared identity across root and detail routes, bound every source-controlled publication string at the renderer boundary. Upstream provenance does not prevent output amplification. Omit over-limit sourced text rather than truncating it; if image credit or license labels are unsafe, reject the complete approved-image presentation and use the non-likeness fallback so no partial rights receipt is published.
- Treat responsive image descriptors as executable browser syntax, not harmless numeric interpolation. Positive-integer checks still admit values that serialize exponentially; apply practical upper bounds to both intrinsic dimensions, fail the complete approved image closed on invalid values, test exact/max+1 plus exponential and non-finite values, and run the real browser image gate. A failure reproduced on clean HEAD is a baseline classification—not a waiver of frozen candidate criteria.
- Gate semantic UI before visual styling: shared identity/freshness continuity, claim-scoped accessible source actions, source-provider semantics, exact runtime hooks, and truthful empty copy must pass before CSS and screenshot review. Validate heading order as an ordered level sequence: reject jumps such as `h1 → h3`, but allow a card `h3` nested under its section `h2`; an assertion that permits only `h1`/`h2` can stay green while cards are absent and then falsely reject the first truthful populated state. Keep paired regressions for the invalid jump and valid `h1 → h2 → h3` path. A visible provider label may stay concise while its accessible name carries the fact context. When requirements say a card needs source URL/type, do not treat the item's content type as its source type: require a finite typed receipt, preserve that type through model projections, and render its mapped label explicitly.
- Treat URL normalization as a provenance boundary. Gate/render equality must be byte-exact or share one projected canonical value; provider-specific identifiers must be derived only after checking the original lexical URL, because parsers erase explicit default ports and other noncanonical syntax. Preserve separate canonical `href` and raw identifier-eligibility values, and design regressions that cannot pass through link omission or unrelated neutral labels. Duplicate-provider all-or-none labeling can mask a broken extractor, so test each defect with a homogeneous pair before adding mixed matrices. Validate website hostnames by DNS label structure and keep the 253-character hostname boundary separate from unrelated display-name caps. See `references/provenance-gate-render-binding.md`.
- Do not use CSS `order` to create a materially different responsive content sequence from the DOM. Reorder the semantic DOM so visual, keyboard-focus, and assistive-technology reading order agree, then verify both mobile priority and desktop layout. Screenshot acceptance alone cannot validate focus or reading order.
- When hydration rewrites server-rendered entity-specific copy, align every runtime capture/validation bound with the renderer publication bound and test the exact maximum. Preserve contextual labels through idle, pending, success, failure, unfollow, and SPA remount states; valid long names must not silently degrade to generic copy.

Review screenshots after the real client runtime runs; verify contextual action labels survive hydration/state transitions, mobile module order matches the product priority, repeated providers remain distinguishable, current items retain item-level source/freshness receipts, relationship names come from reviewed identities rather than slug humanization, partial sets are qualified, and detail routes preserve claim receipts. Do not build or stage the immutable candidate while either reviewer still returns iteration findings.

## Async timeout recovery

A timed-out subagent may have left a coherent partial implementation. First inspect syntax, status, diff, and focused tests. Continue from verified state rather than discarding it. Capture a fresh RED before adding any behavior that the partial implementation did not already cover.

A delegation timeout is transport/process metadata, not the review verdict. Before re-dispatching, inspect the required durable report path: verify it exists, names the exact candidate identity, contains a complete explicit verdict/findings/approval rationale/no-modification statement, and is consistent with a fresh candidate-manifest integrity check. Require the report sidecar to have been generated after final report bytes and to match an independent recomputation. If the report is complete but its original sidecar is stale, preserve both unchanged, classify the run as `timed_out_with_recovered_artifact_and_stale_integrity_metadata`, independently validate the cited source/probe and candidate identity, and create a separately named parent/verifier checksum artifact; never overwrite the stale sidecar or silently present it as valid. If the complete candidate-bound report and integrity evidence are valid, act on its verdict and record that the worker timed out only after preserving the report. If the report is missing, truncated, lacks an explicit verdict, binds the wrong candidate, or cannot be independently integrity-checked, the gate is absent—not failed and not approved.

A broad green suite does not negate a deterministic exact-candidate adversarial reproducer. When a recovered or late report cites a blocking probe, inspect the probe as data, rerun it against the named immutable tree, and verify that it exercises the production contract and demonstrates a concrete consequence. If confirmed, add it as a regression and route the candidate back to remediation even when canonical tests pass.

When re-dispatch is required, use a fresh reviewer at the same clean candidate, provide previously verified canonical evidence, prohibit redundant heavyweight/network/install/browser commands, ask it to write the complete report before optional probes, and keep the original composite or predeclared specialist scope unchanged. A written report does not waive process-exit caveats in executable evidence: passing TAP text under a nonzero wrapper remains case-level evidence, not a clean command PASS. Check and restore any generated artifacts a timed-out reviewer may have left before trusting checkout cleanliness.

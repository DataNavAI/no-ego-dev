# Source-backed feed publication gates

Use this pattern when a product ingests current-card/news records from an aggregator such as Google News RSS and later republishes a reduced record through static generation, APIs, or a database.

## Trust model

An allowlisted outlet label and an HTTPS aggregator URL are not provenance. Treat the RSS parser as an acquisition boundary, not the final publication authority.

Capture and retain all three receipts from the source item:

1. aggregator article URL (`<link>`),
2. publisher label (`<source>` text),
3. publisher origin (`<source url="…">`).

Bind the label to a finite reviewed hostname map. For aggregator URLs, require a canonical host and exact path/token grammar; reject credentials, ports, encoded separators, extra path segments, and malformed tokens. Validate lexical canonicality **before** trusting the parsed URL: URL parsers erase explicit default ports such as `:443`, so checking only `parsed.port` can approve a noncanonical raw receipt. Compare the raw receipt byte-for-byte with the canonical serialized URL (or validate the raw authority separately), and add exact/default-port paired regressions. Apply the same lexical rule independently to the publisher origin: for an origin-only contract, require `parsed.origin === rawPublisherUrl`, plus empty path/query/fragment. Checking `parsed.port === ''` is insufficient because `new URL('https://publisher.example:443').port` is already empty. For direct receipts, apply the same label-to-host map rather than accepting arbitrary HTTPS.

The final publication gate must rerun this binding after normalization. Preserve the publisher origin through every projection that may be revalidated: normalized content, passport/current-card publication projections, compact CMS records, generated data, and public API records. Otherwise the parser may be safe while the final gate either fails valid records or silently drops provenance. When both a declared outlet/publisher label and a rendered receipt label exist, require exact equality across every own-data label; validating one label while rendering another is a provenance substitution bug.

Projection code must also omit absent optional fields rather than materializing them as own properties with `undefined`. Exact-shape cloners and immutable model builders often reject `undefined`, so a direct selection test can pass while every production-normalized current card is later dropped. Exercise the whole path—raw item → normalized item → publication projection → page model → rendered card—and assert a positive card count for represented entities, bounded by the release manifest's maximum.

Treat provenance fields as hostile at **every transformation boundary**, starting with ingestion normalization—not only at the final publication gate. Ordinary property access during normalization can invoke accessors or copy inherited `source`, `outlet`, `publisher`, `publisherUrl`, `sourceUrl`, `sourceType`, trust status, or verification timestamps into own canonical fields; the later own-data gate then sees the laundered values as trusted. Classification helpers, receipt builders, action builders, and canonical record construction must all use own data descriptors and fail closed without invoking getters. If a normalized record retains an original/legacy object, apply the same own-data rule before reading provenance from it.

Projection allowlists must preserve every field used by downstream equality checks. If the final gate compares `outlet`, `source`, and `publisher` with the rendered receipt label, dropping `publisher` in a passport/current-card projection silently disables one branch of that check. Add two end-to-end regressions: (1) inherited/accessor provenance produces `needs_review`, invokes zero getters, and stays unpublishable after normalization; (2) a mismatched own declared `publisher` is rejected by the actual entity current-card selector, not only by the direct publication function.

The exported **final publication function** is itself a hostile-object boundary and must be a **total predicate**: malformed values return `false`; they never throw. Guard `null`, primitives, and arrays before descriptor inspection, and contain the complete decision in a fail-closed exception boundary so hostile or revoked proxies whose reflection traps throw cannot escape into selectors, refresh jobs, page models, or servers. Descriptor-safe normalization does not help direct refresh, runtime, CMS, or database callers that invoke the final gate with an unnormalized object. Read every authorizing field through own-data descriptors: source/action/receipt URLs, receipt type and label, title and entity identity, status and verification state, publication and verification timestamps, publisher origin, and schedule fields. Never invoke getters. Redundant evidence may substitute only when that substitute is also own typed evidence: for example, an own typed receipt can supply source type when top-level `sourceType` is genuinely absent, but inherited `sourceType` cannot. **Descriptor state is part of validation:** if an optional top-level field exists as an accessor or inherited property, reject the record instead of treating it as absent and continuing through receipt/action fallbacks. Apply this rule recursively to receipt entries, primary actions, and retained legacy provenance. When redundant URL representations exist, agreement is an all-representations invariant, not a first-valid-value fallback: collect the own top-level `sourceUrl`, every own typed `sourceUrls[]` receipt URL, and own `primaryAction.url`; reject if any supplied value is malformed or differs byte-for-byte from the URL that will render. Validate sparse arrays, inherited indices, accessor-backed entries, additional receipt entries, and conflicting trusted/untrusted combinations. Do not validate one trusted URL and later expose another through an API or renderer. When both non-URL declarations exist, require exact equality. Require an own `lastVerifiedAt`, and when a typed receipt exists require its own `verifiedAt` to be valid and byte-equal. For entity-bound current coverage, require a non-empty own declared artist and exact agreement with title inference. Build a table-driven regression that moves each authorizing field to the prototype and then to a getter, asserting rejection and zero getter calls; separately test malformed optional properties while otherwise valid own fallback evidence remains present. Include explicit `null`, array, primitive, throwing-proxy, and revoked-proxy calls and assert `false` without an exception.

Treat every selector/projection hop as a second authorization boundary. A projection that keeps only `sourceUrls[0]` can launder an original record whose `sourceUrls[1]` conflicts, even when the final publication function correctly rejects the original. Validate the complete original record first, then validate the exact projected/rendered record; neither check substitutes for the other. Prefer one exact typed receipt when alternates are not a product feature. Enforce the receipt array's exact own shape (`0` and `length`, no sparse/additional numeric, named, or symbol properties) and each receipt object's exact own-data schema; this rejects hidden URL-bearing aliases such as an extra `sourceUrl`. Validate the container prototype too: reject custom array/object prototypes and inherited extra numeric, named, symbol, or URL-bearing provenance. Preserve intentional prototype-pollution regressions where an own valid property shadows an inherited same-index property; the validator must distinguish a shadowed inherited `0` from an unshadowed inherited `1` rather than rejecting every polluted prototype indiscriminately. For action objects that legitimately carry UI metadata, use an explicit optional-key allowlist (for example own-data `url`, `label`, and `kind`) instead of either demanding URL-only shape or allowing arbitrary extra URL-bearing aliases. Include direct-final-gate, entity-selector, API-projection, and renderer regressions for a trusted first receipt plus attacker-controlled secondary/named/symbol receipt data. When prototype-pollution tests intentionally install a non-writable numeric property on `Object.prototype`, avoid `push()` into empty scratch arrays used by the gate; append with an own data-property definition so the validator itself neither crashes nor silently skips evidence.

Entity selectors are another hostile identity boundary. Validate `primaryArtistSlug`, `group`, and `idol` descriptors before branching by entity type or applying fallback identity rules. The same validation must cover individuals and groups: a malformed authoritative `primaryArtistSlug` must reject the record rather than falling through to a matching `idol` or `group`. **Descriptor presence—not value truthiness—controls fallback:** an own authoritative descriptor whose value is `null`, `undefined`, malformed, or conflicting must reject; only complete descriptor absence may authorize the documented secondary fallback. A valid, explicitly present authoritative primary identity is also exclusive and must agree with every explicitly present redundant identity for the same entity type: reject both directions of contradiction—wrong primary plus matching secondary, and matching primary plus wrong/malformed secondary. Do not stop validating secondary identity merely because the primary already matched. Add (1) a throwing-getter regression that would select through fallback if descriptor validation were missing, (2) both directions of valid-but-conflicting primary/secondary identity, and (3) own `null` and own `undefined` primary and secondary regressions; assert zero selected items and zero getter calls where applicable.

Add regressions for inherited publisher origins and throwing getters, then exercise the actual current-card selection path—not just direct publication validation—to prove the receipt survives every projection.

## Refreshing compact and canonical receipts

A bounded refresh may legitimately receive two record shapes:

- a compact parser record with one own `sourceUrl` and no `sourceUrls` array;
- a canonical record with one exact typed receipt in `sourceUrls[0]`.

Do not require the canonical receipt array merely to advance a compact parser record. Instead, clone through the hostile-object snapshot boundary, require either a valid compact URL or an exact canonical receipt, and reject records having neither. Preserve every source URL byte-for-byte—refresh verification must never normalize, replace, redirect, or synthesize a different URL. For canonical records, update the receipt's `verifiedAt` together with top-level `lastVerifiedAt`; for compact records, update only `lastVerifiedAt` and do not invent a receipt that lacks trustworthy label/type provenance.

Keep refresh authorization fail-closed on both sides of the timestamp rewrite: run the complete final publication predicate before cloning/rewriting and again against the emitted clone before counting it. A malformed or conflicting optional `sourceUrls` property must reject rather than fall back to an otherwise valid compact `sourceUrl`; only genuine descriptor absence permits the compact path. Add paired tests for (1) a parser-shaped trusted compact record that remains publishable, keeps the exact source URL, and advances the run/verification clock, and (2) malformed, empty, accessor-backed, inherited, or conflicting receipt metadata that produces no accepted row and invokes no getter.

Treat refresh timestamps as provenance, not decoration. `updatedAt`, `lastRunAt`, and `lastSuccessfulRunAt` may advance only for a refresh candidate that satisfies the configured minimum after final-gate revalidation. Every accepted row's top-level verification time—and canonical receipt time when present—must equal the candidate clock. Verify that publication times are not in the future beyond policy skew, URLs are unique after deduplication, and `fetchedItemCount`, `publishedItemCount`, and accepted-row count retain their documented distinct meanings. Never infer successful verification merely because two caller-controlled timestamps match.

## Headline safety

Do not fix editorial leakage by deleting today's rows or adding only the names found in one review. Use two layers:

- reviewed identity matching for known groups and artists;
- conservative structural rejection for coordinated names and editorial patterns.

Derive identity mentions from the product's reviewed group/idol catalog rather than maintaining a second narrow denylist. Normalize names once, exclude demonstrably ambiguous common-word identities, and ignore only the aliases that identify the selected primary entity. Treat group-owned and member-owned headlines as distinct: a group mention plus a reviewed member mention is not automatically a group card. Handle punctuation-split member names (for example a one-word catalog alias appearing as two hyphen-separated title tokens) by exact bounded adjacent-token windows—join two or three complete normalized tokens and compare for equality. Never search the fully compacted title with substring matching; that creates cross-word false positives such as an alias appearing accidentally across “with anniversary.” Pair every split-alias rejection with a valid group-only control that contains similar surrounding words. The reviewed catalog cannot enumerate every external collaborator, so structural rejection must not depend on the secondary name being cataloged or capitalized. Detect coordination **bidirectionally** (`external and Primary` as well as `Primary and external`), normalize punctuation-heavy primary aliases before matching (for example names containing parentheses or hyphens), and cover both immediate coordination and non-immediate collaboration framing such as `Primary announces collaboration with external` or `Primary teams up with external`. Normalize separator symbols into one coordination token before matching so comma, plus, colon, semicolon, slash, pipe, ampersand, and dash variants exercise the same rule; retain standalone-`x` coverage. Do not normalize only whitespace-surrounded dashes: `Primary-external`, en-dash, and em-dash forms are equivalent bypasses. Replacing every hyphen globally is also wrong because it destroys legitimate aliases such as `(G)I-DLE`. Do not treat punctuation alone as proof of coordination. For ambiguous dashes, first bound title length before any per-dash slicing/normalization; otherwise a delimiter-heavy hostile title can turn a publication check into quadratic work. Then inspect each dash while preserving punctuation-heavy primary aliases. Require explicit collaboration/release/announcement framing **and** plausible secondary-subject evidence. One reusable policy is to split the non-primary side at the first action verb, classify the pre-action phrase as a counterpart only when it matches a reviewed one-token identity or a bounded multi-token name-like phrase, and maintain a reviewed descriptor vocabulary for legitimate appositives/publishers such as “pop icons,” “global superstars,” “members,” agencies, and labels. The structural multi-token path ensures protection does not rely solely on a finite external-artist list; the descriptor controls prevent “every unknown word is an artist” false positives. Normalize possessive primary aliases (`Primary’s—…`) before boundary matching. Pair every hostile row with valid single-artist controls for ASCII hyphen, spaced hyphen, en dash, em dash, punctuation-heavy aliases, possessives, both artist positions, and each framing verb (`announce`, `release`, `collaborate`). Include valid action-led and descriptor-led forms such as `Primary—releases a new album`, `Primary—pop icons announce…`, and `Primary—Label announces…`. Freeze this two-sided matrix before review so corrections improve the semantic boundary rather than oscillating between leakage and blanket rejection. Fail closed if the structure indicates a second subject even when that subject is lowercase and absent from the reviewed catalog. **Catalog load or shape failure must fail publication closed** (or fail module/startup initialization); never fall back to an incomplete alias list, because that widens publication exactly when the authoritative identity boundary is unavailable.

Build the RED matrix before implementation. Include:

- connectors: `and`, `with`, `joins`, `feat`, `featuring`, `versus`, `vs`, `alongside`, `&`, standalone `x`;
- case and punctuation: uppercase connectors, commas, semicolons, slashes, parentheses, dashes, and lowercase known names;
- clickbait: question marks, interrogatives both at the start and after an artist prefix, auxiliary-question starts, “won't believe”, “truth/revealed/exposed”, “secret/shocking/surprise”;
- gossip: dating, romance, relationship, rumors, speculation, claims, and “love life”.

Run the same hostile titles directly against the final publication function, not only through the parser. Direct database/CMS insertion is the critical bypass path.

## Volatile inventory tests

Separate deterministic taxonomy/rendering fixtures from live reviewed inventory. For a nontrivial-current-inventory assertion, evaluate at the committed inventory's own reviewed refresh timestamp rather than an unrelated historic fixed clock. Keep the minimum meaningful (`> 5`, product threshold, or equivalent) instead of weakening it to one item merely because the clock drifted.

After changing parser policy:

1. record focused RED;
2. implement the generalized boundary;
3. rerun the real refresh;
4. editorially inspect the resulting titles;
5. run focused, canonical, browser, and build checks;
6. restore generated output;
7. obtain fresh immutable specification, security, and editorial verdicts.

## Common failure modes

- Adding a finite outlet allowlist but not binding labels to publisher origins.
- Validating provenance in the parser but not after normalization/API compaction.
- Preserving `publisherUrl` only inside a legacy blob that public projections discard.
- Validating `item.outlet` while rendering a different `sourceUrls[0].label`.
- Reading provenance through inheritance or getters instead of own data descriptors, including during normalization where hostile values can be laundered into own canonical fields.
- Omitting one declared label field (for example `publisher`) from a downstream projection and thereby disabling an exact-label comparison.
- Falling back to an incomplete identity list when the reviewed catalog is unavailable.
- Emitting absent optional fields as own `undefined` properties, then losing every record at an exact-shape clone boundary.
- Testing selection but not normalized page-model/rendered-card production paths.
- Using `[^/]+` for opaque path tokens; this accepts encoded separators such as `%2F`.
- Testing only lowercase, space-delimited connectors.
- Relaxing a live-inventory count assertion when the real issue is a mismatched test clock.
- Treating 200 responses from source links as editorial approval.

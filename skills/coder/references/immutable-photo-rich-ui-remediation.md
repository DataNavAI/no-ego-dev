# Immutable Photo-Rich Static UI Review Remediation

Use this after an independent review finds that a static/generated UI looks correct in its currently reachable empty or unavailable state but may regress when validated content becomes ready, at desktop breakpoints, or when approved media fails at runtime.

## Core rule

A screenshot of the currently reachable state is not sufficient evidence for every renderer state. Freeze one candidate only after executable coverage proves both:

- the current unavailable/empty path remains truthful and visually anchored; and
- a synthetic but schema-valid ready path preserves the same approved visual identity without inventing production availability.

## RED → GREEN remediation sequence

1. Bind every finding to the reviewed head/tree and mark that verdict obsolete as soon as remediation begins.
2. Add one failing behavior test per material finding before production edits:
   - ready Learn/detail output for an eligible identity contains the manifest-bound image and canonical alt text;
   - ready Challenge/journey output contains the intended dominant image above the primary interaction;
   - desktop exposes the complete primary route set with equivalent `aria-current` semantics;
   - an approved-image error replaces the failed image once with a designed local fallback.
3. Run the focused tests and record the expected RED reason. Distinguish missing behavior from syntax, import, or fixture errors.
4. Implement the smallest shared behavior:
   - derive ready-state media through the same manifest projection used by unavailable/discovery surfaces;
   - share primary-nav markup between mobile and desktop treatments so route/current semantics cannot drift;
   - install one root-level captured `error` listener rather than inline handlers;
   - allow fallback replacement only for exact canonical public media paths;
   - use `WeakSet` identity to make root wiring and failed-image replacement idempotent;
   - create fallback DOM nodes with DOM APIs, preserve trusted layout classes, mark the generic replacement `aria-hidden`, and retain adjacent visible identity copy.
5. If browser boot tests use fake roots, make those fixtures implement the real EventTarget seam (`addEventListener`). Otherwise boot may fail before the intended dependency boundary and a recovery test can pass for the wrong reason.
6. Add explicit full-frame CSS for both forms of fallback:
   - replacement fallback nested inside an existing media frame;
   - ready-state fallback that is itself the media frame and therefore carries both frame and fallback classes.
7. Run focused GREEN, then each canonical command as a fresh bare invocation after the final edit: full tests, build, public boundary, mock/content checks, architecture checks, audit, diff/whitespace, and configured secret scans.

## Browser evidence

Exercise the generated output with a real browser at all required mobile widths and at least one desktop width. Assertions should prove behavior, not merely CSS implementation details:

- no horizontal overflow;
- mobile fixed navigation has bottom clearance and the desktop nav is hidden;
- desktop mobile nav is hidden **and** the desktop route set is visible, ordered, clickable, and carries the expected current route;
- approved images use canonical local paths and meaningful alt text;
- unavailable states remain truthful;
- dialog open/close, Escape, overflow, and focus restoration work;
- dispatching an image `error` on a canonical media element produces the designed fallback without console errors.

A dependency-free CDP harness is acceptable when it drives a real installed Chromium-family browser and keeps scripts, profiles, screenshots, and reports outside the repository.

For timing-sensitive focus assertions, rerun the unchanged exact candidate once when one sample fails but an equivalent focus path passes and previous exact runs passed. Treat a repeatable failure as product behavior; treat a single non-reproducible sample as harness timing, and retain only the final truthful report.

## Immutable evidence discipline

- Any source, test, CSS, generated artifact, or evidence-script assertion change invalidates earlier candidate evidence.
- Rebuild before browser QA so the server reads current generated bytes.
- Commit and push only after local gates pass; resolve full head, tree, base, remote branch, and PR-head parity.
- Bind the local-only report to that exact head/tree and rerun once against the immutable commit.
- Update the PR with sanitized scratch-relative evidence paths, never absolute home paths.
- Re-dispatch independent spec, ordinary-quality, and visual reviews against the new exact head. Never transfer approval from the pre-remediation commit.

## Review checklist

- [ ] Ready and unavailable states are independently exercised.
- [ ] Eligible media survives ready-state controller rerenders.
- [ ] Ineligible ready states retain a full-sized non-likeness fallback.
- [ ] Desktop routes remain reachable after mobile navigation is hidden.
- [ ] Runtime media failures preserve layout without inline handlers.
- [ ] Browser fakes exercise the intended failure boundary.
- [ ] Final browser report is bound to the pushed immutable SHA/tree.
- [ ] All prior verdicts were discarded and exact-head re-reviews requested.
